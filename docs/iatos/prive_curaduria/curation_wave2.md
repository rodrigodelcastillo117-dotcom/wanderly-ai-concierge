# Curation wave 2 — rules on top of curation_brief.md (these override it where they differ)

1. All your destinations are NEW (no existing rows): skip every keep/replace instruction.
2. Every entry has `universe`: one of the_table, after_dark, casino_grand_nights, yacht_sea, private_stays, iconic_events, culture_access, wellness_escape, adventure_elite, sport_leisure, celebrations, signature_mexico. Keep `category_group` too (the_table / after_dark / extraordinary) for compatibility.
3. Images: do NOT search Wikimedia or press kits. Add `"image_query"`: 3–6 English keywords describing the place type and setting for a Pexels search (e.g. "alpine ski chalet terrace sunset", "Kyoto ryokan garden"). The app labels it "Foto ilustrativa · Pexels · <fotógrafo>".
4. Geography (no duplicates): add `"locality_type"` (city | neighborhood | region | island | resort_area | country) and `"parent_destination"` (e.g. Polanco → "Ciudad de México"; Beverly Hills / Malibu → "Los Ángeles"; Miami Beach → "Miami"; San José del Cabo / Todos Santos → "Los Cabos" region / Baja California Sur; Riviera Maya → "Quintana Roo"; Omán → country-level with locality Muscat). `city_key` = kebab-case ASCII of the destination (e.g. "st-moritz", "costa-amalfitana", "san-jose-del-cabo").
5. Depth: 8–12 genuinely extraordinary, verified entries per destination, spread over at least 5 universes that fit the place (ski resorts → sport_leisure, private_stays, the_table, wellness_escape, after_dark; islands → yacht_sea, private_stays, wellness_escape, celebrations…). Quality over quantity: fewer verified entries beat many weak ones. Seasonal venues: state the season if sourced.
6. Casino entries: legally licensed, informational only (no betting, deposits, bonuses, affiliate links); note age rules if sourced. Adventure: only authorized operators with stated safety requirements.
7. Never invent names, awards, prices, VIP access, partnerships, availability or hours. Prices only when an official/primary source shows them (with currency and the date seen); otherwise null. Use web search and open the pages you cite; when unsure mark no_confirmado.
8. Validate your JSON parses (node -e) and report per destination: number of entries, universes covered, how many verified vs no_confirmado, and anything you could not verify.
